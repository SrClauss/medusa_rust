### Tarefa 1.1: Modelos e Migração

Criar migração para tabela `roles` e `user_roles`.

```sql
CREATE TABLE roles (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL UNIQUE,
  permissions text[] NOT NULL DEFAULT '{}',
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE user_roles (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role_id uuid NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_user_roles_user ON user_roles(user_id);
``` 

Adicionar structs em `src/models.rs`:

```rust
#[derive(sqlx::FromRow, Debug)]
pub struct Role {
    pub id: uuid::Uuid,
    pub name: String,
    pub permissions: Vec<String>,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub updated_at: chrono::DateTime<chrono::Utc>,
}

#[derive(sqlx::FromRow, Debug)]
pub struct UserRole {
    pub id: uuid::Uuid,
    pub user_id: uuid::Uuid,
    pub role_id: uuid::Uuid,
    pub created_at: chrono::DateTime<chrono::Utc>,
}
```

### Tarefa 1.2: Serviço de Role

Implementar `RoleService` com métodos CRUD e `has_permission(user_id, perm)`.
Exemplo:

```rust
pub struct RoleService {
    pool: sqlx::PgPool,
}

impl RoleService {
    pub async fn list(&self) -> anyhow::Result<Vec<Role>> { /* SELECT */ }
    pub async fn create(&self, name: &str, perms: &[&str]) -> anyhow::Result<Role> { /* INSERT */ }
    pub async fn add_role_to_user(&self, user_id: Uuid, role_id: Uuid) -> anyhow::Result<()> { /* INSERT */ }
    pub async fn user_permissions(&self, user_id: Uuid) -> anyhow::Result<Vec<String>> { /* JOIN roles */ }
    pub async fn user_has(&self, user_id: Uuid, perm: &str) -> anyhow::Result<bool> { /* permissions.contains */ }
}
```

### Tarefa 1.3: Middleware de Autorização

Adicionar função `require_permission()` que pode ser aplicada nas rotas
Axum:

```rust
pub async fn require_permission<B>(
    State(state): State<AppState>,
    Extension(user): Extension<AuthenticatedUser>,
    perm: String,
    next: Next<B>,
) -> Result<impl IntoResponse, AppError> {
    if state.role_service.user_has(user.id, &perm).await? {
        Ok(next.run().await)
    } else {
        Err(AppError::Forbidden)
    }
}
```

Use o macro `axum_extra::middleware::from_fn_with_state`.

### Tarefa 1.4: Rotas de Administração

Criar rotas `GET/POST /admin/roles`, `POST /admin/users/:id/roles` etc.
Proteger com permissão `roles.manage`.

### Tarefa 1.5: Atualizar sistema de JWT

Ao gerar token incluir `roles` ou `permissions` no payload para evitar
consulta em cada request; recordar no middleware de autenticação.

## PARTE 3: Multi-language

### 📚 Referência

```
vendor/medusa_js/packages/medusa/src/models/product.ts  # fields i18n
vendor/medusa_js/packages/medusa/src/services/language.ts
```

### Tarefa 3.1: Migração SQL

Adicionar tabela `languages` e `product_translations`:

```sql
CREATE TABLE languages (
  code text PRIMARY KEY, -- "en", "pt-BR", etc
  name text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE product_translations (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  product_id uuid REFERENCES products(id) ON DELETE CASCADE,
  language_code text REFERENCES languages(code),
  title text,
  description text,
  UNIQUE(product_id, language_code)
);
```

### Tarefa 3.2: Middleware de Locale

Extraia `Accept-Language` ou parâmetro `?locale=`. Salve em `RequestExtension`.

### Tarefa 3.3: Service de Tradução

`LanguageService` que retorna `title/description` de um produto para a
língua atual, caindo no valor padrão se não houver tradução.

### Tarefa 3.4: API

- endpoints `POST /admin/languages`, `POST /admin/products/:id/translations`;
- parâmetro global `?locale` para todas as rotas store;
- campos `title`, `description` em `ProductResponse` são localizados.
